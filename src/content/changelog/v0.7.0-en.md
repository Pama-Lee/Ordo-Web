The engine changes in this entry ship with `@ordo-engine/cli` 0.6.1 and 0.7.0.

## Engine

- New decimal type for exact money math, with no floating point drift. Numeric equality, division and `round(x, n)` were fixed along the way.
- A ruleset can declare an `inputSchema`. Missing or mistyped input fields return 400 `INVALID_INPUT` instead of quietly taking the wrong branch.
- Assignments and outputs accept expression strings, such as `"price * qty"`.
- New `decision_table` step. `hitPolicy` supports `first` (first matching row) and `collect` (every matching row, optionally reduced with sum, count, min or max).

## CLI

- `ordo impact <ruleset>` runs your working copy next to the last version in git, over test cases, real inputs you provide and probe inputs generated on both sides of every threshold, and lists the inputs whose result changed. Supports `--json` and `--fail-on-change`.
- `ordo mcp` gains an `impact` tool, so coding agents can check the effect of their own rule edits.
- `ordo guard upgrade` brings Guard policies scaffolded by older versions up to the current default policy.

## Rule packs

- New `examples/rule-packs/` in the repository: credit approval, promo stacking and fraud scoring. Each is a complete Ordo project with tests that runs with `ordo test`.
