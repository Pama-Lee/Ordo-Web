## 問題

很多團隊都碰到過這些情況：

- 改一個折扣規則，要提 PR、做程式碼審查、發版、上線
- 風控策略分散在三個微服務裡，沒人說得清完整邏輯
- 產品經理想看當前生效的審批流程，找不到一個能查的地方

原因都一樣：業務決策邏輯和應用程式碼寫在了一起。

## 做法

規則引擎做的事情是把「做什麼決策」和「怎麼執行決策」分開。

在 Ordo 裡，決策邏輯用 JSON 或 YAML 描述，透過 API 執行，結果返回給呼叫方。修改決策邏輯不需要重新部署應用。

## Ordo 的特點

1. 執行快：基於 Rust 和 Cranelift JIT，單次執行在一微秒以內
2. 視覺化編輯：不寫程式碼的同事也能在 Studio 裡看規則、改規則
3. 版本控制、審計日誌和回滾
4. 多種接入方式：HTTP、gRPC、WASM、CLI

如果你們的團隊也被業務規則的管理問題困擾，可以試試 Ordo。
