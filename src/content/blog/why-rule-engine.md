## 问题

很多团队都碰到过这些情况：

- 改一个折扣规则，要提 PR、做代码审查、发版、上线
- 风控策略分散在三个微服务里，没人说得清完整逻辑
- 产品经理想看当前生效的审批流程，找不到一个能查的地方

原因都一样：业务决策逻辑和应用代码写在了一起。

## 做法

规则引擎做的事情是把“做什么决策”和“怎么执行决策”分开。

在 Ordo 里，决策逻辑用 JSON 或 YAML 描述，通过 API 执行，结果返回给调用方。修改决策逻辑不需要重新部署应用。

## Ordo 的特点

1. 执行快：基于 Rust 和 Cranelift JIT，单次执行在一微秒以内
2. 可视化编辑：不写代码的同事也能在 Studio 里看规则、改规则
3. 版本控制、审计日志和回滚
4. 多种接入方式：HTTP、gRPC、WASM、CLI

如果你们的团队也被业务规则的管理问题困扰，可以试试 Ordo。
